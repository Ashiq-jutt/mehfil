## 5. VOICE — AGORA RTC

Use **Agora RTC** for actual live voice communication.

Do NOT build raw WebRTC infrastructure for the MVP.

Each Firestore room maps to an Agora channel.

Example:

```text
Firestore Room ID:
abc123

Agora Channel:
abc123
```

Flow:

```text
React Native
     ↓
Cloud Function
     ↓
Generate Agora RTC Token
     ↓
React Native
     ↓
Agora RTC
     ↓
Live Voice Room
```

IMPORTANT:

Never expose the Agora App Certificate in React Native.

The Agora App Certificate must only exist in Firebase Cloud Functions/server-side environment.

Create a secure Cloud Function that:

1. Verifies Firebase authentication.
2. Checks that the user belongs to the room.
3. Generates a short-lived Agora RTC token.
4. Returns the token and channel information.

Examples:

* User can update their own profile.
* User cannot modify another user's coins.
* User cannot change their own role.
* User cannot make themselves room owner.
* Only room owner/admin can promote moderators.
* Only authorized moderators can remove/ban members.
* Users cannot directly create arbitrary wallet transactions.
* Challenge rewards cannot be claimed repeatedly.

All sensitive business operations should go through Cloud Functions.

## 23. COST/PERFORMANCE AWARENESS

This app can generate a large number of Firestore reads.

Therefore:

* Avoid unnecessary realtime listeners.
* Unsubscribe listeners on unmount.
* Use pagination.
* Use limited queries.
* Avoid repeatedly fetching unchanged data.
* Cache appropriate data locally.
* Denormalize carefully when it reduces expensive reads.
* Use Cloud Functions for aggregation.
* Avoid listening to entire collections.

Design Firestore specifically for realtime social-app usage and cost efficiency.
